## 1. 背景与目标

### 1.1 现状

研究室目前用打印机自带的网页界面（CentreWare Internet Services）提交打印：
`http://<打印机地址>/print.htm`

存在的问题：

- **界面陈旧**：HTML 4.01 Frameset，用 `document.write` 生成表格布局，固件是 2015 年的，没有响应式设计，手机上基本没法用。
- **操作繁琐**：打印设置、选文件、提交按钮分散在不同区域；每次都要重新设置（双面、黑白等）；一次只能选一个文件。
- **信息分散**：打印机状态、纸盒余量、碳粉余量、作业队列、作业历史分别在不同的标签页/框架里，需要来回切换。
- **单一语言**：界面语言由打印机管理员全局设定（当前为日语），不懂日语的人用起来不方便。
- **反馈不足**：提交后很难确认作业有没有进入队列、有没有打印完成。

### 1.2 目标

1. 提供**现代化、简洁、响应式**（PC / 平板 / 手机）的打印管理界面。
2. **零额外设备、零费用**：不需要服务器，也不需要常开的电脑。
3. **使用门槛低**：每台电脑只需一次性的简单设置（约 10 秒），之后和现在一样打开打印机网址即可使用。
4. **多语言**：界面可随时切换语言，首期支持 **日语（ja）** 和 **英语（en）**，架构上可以低成本扩展（如中文）。
5. 把「提交打印 / 打印机状态 / 作业队列与历史」整合到一个界面中。

### 1.3 非目标（首期不做）

- 管理员功能（重启、关机、网络设置、用户管理等）：继续用原厂界面。
- 扫描、传真、地址簿等非打印功能。
- 计费/配额管理、用户登录认证。
- 替代驱动打印（在 Word 等软件里按 Ctrl+P 打印仍走原有驱动）。

## 2. 部署方案：为什么不需要服务器

### 2.1 前提条件（已确认）

- 研究室**没有常开的电脑**，也**不会为此购买**服务器或树莓派。
- 分发"本地 HTML 文件"让大家自己打开，操作麻烦，也容易用错，**不采用**。
- 只在**研究室网段**内使用。

### 2.2 为什么现在的 `print.htm` 不需要服务器就能访问？

因为**打印机本身就是一台服务器**：它的固件里内置了一个小型 Web 服务器，打印机通电联网后就一直在提供网页。
但这些页面是厂商写死在固件里的，**我们没法把自己的文件放到打印机里**。

### 2.3 核心思路：让新界面"运行在打印机的网页里"

浏览器有一条安全规则（同源策略）：**只有打印机自己的网页**才能读取打印机的数据、向打印机提交打印。v0.1 里需要中转服务器，就是因为这条限制。

但**可以由用户在打印机网页上"点一下"**，把新界面的程序加载到这个页面里：

1. 用户像现在一样打开 `http://<打印机地址>/`。
2. 点一下浏览器书签栏里的「🖨 Print Portal」按钮（**书签小程序 / bookmarklet**）。
3. 书签从网上加载新界面的程序（一个 JS 文件），把旧页面**整个替换**成新界面。
4. 新界面运行在打印机自己的网页里，属于**同一来源**，因此可以直接读取状态、提交打印，**中间不需要任何服务器**。

```
  ┌─────────────── 用户的浏览器（标签页：http://<打印机地址>/）───────────────┐
  │                                                                          │
  │   ① 打开打印机网址  ─▶  旧界面（Frameset）                                   │
  │   ② 点击书签       ─▶  从 GitHub Pages 加载 portal.js ◀──── 互联网（免费托管） │
  │   ③ portal.js 把页面替换为新界面                                             │
  │                                                                          │
  │      新界面 ── 同源 fetch ──▶ /sttray.htm /jblist.htm …（读状态）            │
  │             ── 同源 POST ──▶ /UPLPRT.cmd（提交打印）                         │
  └──────────────────────────────────┬───────────────────────────────────────┘
                                     │ 研究室局域网（HTTP）
                                     ▼
                            ApeosPort-V C4476（<打印机地址>）
```

### 2.4 可行性验证（2026-11-25，用 Chrome 实测）

在打印机页面上注入脚本（等同于点击书签），验证结果如下：

| 验证项 | 结果 |
|---|---|
| 打印机页面是否有阻止外部脚本的安全策略（CSP） | ✅ 所有页面都没有 CSP，只有 `X-Frame-Options`（不影响本方案） |
| 注入的脚本能否读取打印机数据（`fetch('/sttray.htm')`） | ✅ 可以，成功读取纸盒数据 |
| 能否由浏览器直接提交打印（`FormData` → `POST /UPLPRT.cmd`） | ✅ 可以，打印机正常响应（测试时用空文件，打印机返回 `REQUEST: ERROR`，没有出纸） |
| 能否把旧页面整个替换为新页面 | ✅ 可以 |
| 能否在 HTTP 的打印机页面里加载 HTTPS 外部脚本 | ✅ 可以 |

### 2.5 用户的一次性设置

每台电脑、每个浏览器只需做一次：

1. 打开**安装页面**（托管在 GitHub Pages，有日/英说明和动图）。
2. 把页面上的「🖨 Print Portal」按钮**拖到浏览器的书签栏**。

之后每次打印：**打开打印机网址 → 点书签**。可以把打印机网址也加进书签栏，变成"点两下"。

> **已确定：首期以书签方式为主。** 浏览器扩展作为后续可选增强（M5）：安装后访问打印机网址时会**自动**切换到新界面，刷新也不会变回旧界面。但上架 Chrome 网上应用店需要一次性 5 美元的开发者注册费（Edge、Firefox 免费），Safari 需要付费的 Apple 开发者账号，所以先用书签上线、收集反馈，再决定是否做扩展。界面和打印机适配层只写一份，书签和扩展只是不同的"启动方式"（`src/loader/`），因此以后加扩展不需要重写。
>
> 扩展的设计要点（预留）：打印机网址由用户在扩展的设置页填写，运行时动态申请该网址的权限（`chrome.permissions.request` + `chrome.scripting.registerContentScripts`），**扩展包里不写打印机 IP**。

### 2.5.1 新旧界面并存

打印机本身没有任何改动，旧界面始终可用：

| 用户 | 默认看到 | 切换 |
|---|---|---|
| 什么都不装 | 旧界面 | — |
| 使用书签 | 旧界面 | 点书签 → 新界面；刷新 → 旧界面 |
| 使用扩展（后续） | 新界面 | 点「返回原厂界面」→ 旧界面 |

不强制任何人改变习惯，可以逐步推广。

### 2.6 方案比较（存档）

| 方案 | 需要设备 | 费用 | 用户操作 | 结论 |
|---|---|---|---|---|
| **A. 书签小程序（本方案）** | 无 | 0 | 一次性拖拽书签；每次点一下 | ✅ **采用** |
| B. 浏览器扩展 | 无 | 0–5 美元 | 一次性安装；之后全自动 | ⏳ 后续可选（M5，与 A 共用同一套代码）；体验最好，但不支持 Safari、需审核 |
| C. 局域网内的中转服务器（v0.1 方案） | 常开电脑 / 树莓派 | 0–1.5 万日元 | 无 | ❌ 没有设备 |
| D. 分发本地 HTML 文件 | 无 | 0 | 每人保存文件、每次手动打开；无法读取状态 | ❌ 麻烦，功能也受限 |
| E. 部署到外部网站，直接访问打印机 | 无 | 0 | — | ❌ 被浏览器的同源策略和混合内容限制拦截 |

### 2.7 本方案的限制

| 限制 | 影响 | 应对 |
|---|---|---|
| 刷新页面后会变回旧界面 | 需要再点一次书签 | 新界面内部的页面切换不刷新页面（单页应用）；后续可用浏览器扩展彻底解决 |
| 手机上使用书签小程序比较麻烦 | 手机打印不方便 | 首期以 PC 为主；界面本身仍做响应式；手机端的书签设置写在安装页的说明里 |
| 无法使用 SNMP（浏览器不支持） | 碳粉余量在打印机网页上只有 **25% 一档、向上取整**的值（见 13.2 第 7 条） | 由开发者本机定时用 SNMP 测量并发布精确值（第 14 章）；没有可用的精确值时按范围显示（如「1〜25%」） |
| 依赖 GitHub Pages 加载程序 | GitHub 无法访问时新界面不可用 | 原厂界面始终可用，作为备用 |
| 设置保存在各自的浏览器里 | 换电脑后需重新设置常用选项 | 影响很小 |

## 3. 打印机调查结果

### 3.1 设备信息

| 项目 | 内容 |
|---|---|
| 型号 | FUJI XEROX **ApeosPort-V C4476**（彩色多功能机，固件 2015） |
| IP | 属于大学的**全局 IP** 段（具体地址只在研究室内部告知，不写入公开仓库） |
| Web 界面 | CentreWare Internet Services，UTF-8，Frameset 结构，**无需登录**即可打印和查看状态 |
| 当前显示语言 | 日语（打印机全局设定） |

### 3.2 开放的服务

| 端口/协议 | 状态 | 说明 |
|---|---|---|
| TCP 80（HTTP） | ✅ 开放 | Web 界面、网页提交打印（**本方案使用**） |
| TCP 443（HTTPS） | ❌ 关闭 | — |
| TCP 631（IPP） | ❌ 关闭 | — |
| TCP 9100（RAW） | ❌ 关闭 | — |
| TCP 515（LPD） | ✅ 开放 | 驱动打印用的通道；浏览器无法使用 |
| UDP 161（SNMP v2c） | ✅ 可读 | 浏览器无法使用 |

### 3.3 网页提交打印的接口

以 `multipart/form-data` 格式 `POST` 到 **`/UPLPRT.cmd`**，字段如下：

| 字段 | 含义 | 取值 |
|---|---|---|
| `FILE` | 打印文件 | 二进制文件 |
| `CPN` | 份数 | 1–999 |
| `COLT` | 逐份（ソート） | `NO`（不指定）/ `ON` / `OFF` |
| `DUP` | 双面 | `NO`（单面）/ `DP`（长边装订）/ `TB`（短边装订） |
| `CLR` | 颜色模式 | `AUTO` / `CLR`（彩色）/ `BW`（黑白） |
| `IT` | 纸盒 | `AUTO` / `T1`–`T4` / `SMH`（手送纸盒 5） |
| `SIZ` | 纸张尺寸 | `NUL`（不指定）/ `A3` / `B4` / `A4` / `B5` / `A5` / `LT` / `FL` / `LG` / `I15` / `LD` |
| `MED` | 纸张类型 | `NUL` / `NR`（普通纸）/ `HQ`（上质纸）/ `RC`（再生纸）/ `U1`–`U5`（用户纸张） |
| `DEL` | 打印类型 | `IMP`（普通）/ `PRP`（样张打印）/ `DLY`（定时打印）/ `SECP`（安全打印），见 4.3 |
| `PPUSR` | 样张打印用户 ID | 最长 24 字符 |
| `HOUR` / `MIN` | 定时打印时间 | 0–23 / 0–59 |
| `SPUSR` | 安全打印用户 ID | 最长 24 字符 |
| `SPID` / `RSPID` | 安全打印密码 / 确认 | 0–12 位数字；不使用时原界面发送 `************` |
| `ESPID` | 密码是否被修改 | `on` / `off` |

本机只有中央出纸盘，没有出纸盘选项（`OT`）。

### 3.4 状态/作业数据的获取方式

打印机各页面把数据以 **JavaScript 数组字面量** 的形式写在 HTML 里，新界面用 `fetch` 取回 HTML 后解析：

| 页面 | 变量 | 内容与格式 |
|---|---|---|
| `stgen.htm` | `spcs`, `artinfo` | 设备名、IP、状态文本（如「節電中」）、通知/警告信息 |
| `sttray.htm` | `infoIn`, `infoOut` | 纸盒：`[名称, 状态索引, 余量%, 尺寸, 颜色, 纸张类型, 优先级, …]`；状态 `0=良好 1=缺纸 2=未知 3=不可用` |
| `stsply.htm` | `info`（多次 `concat`） | 耗材：`[类别, [[名称, 状态码, 余量%, 日期], …], 种类]`，例：`['ブラックトナー(K)',7,50,'----/--/--']` |
| `jblist.htm` | `info` | 队列：`[作业ID(16进制), 作业名(已遮蔽), 所有者, 状态索引, 类型索引, 已完成份数]`；状态 `0=等待 1=执行中 2=暂停 3=待机 4=完成` |
| `jbhist.htm` | `jHst` | 历史：`[作业名(已遮蔽), 所有者, 结果索引, 类型索引, 页数, 出纸盘, 接口, 完成时间]`；结果 `1=正常 2/3=警告 4–6=强制终止 8=异常` |
| `sperr.htm` | `errLog` | 错误历史：`[时间, 错误代码]`，如 `016-788` |

### 3.5 M0 实测结果（2026-11-25，共打印 3 页测试页）

| # | 测试 | 结果 |
|---|---|---|
| 1 | 网页通道提交 1 页 PDF（双面长边 · 黑白 · A4） | ✅ HTTP 200，`<TITLE>REQUEST: ACCEPTED</TITLE>`，约 2 秒；正常打印 |
| 2 | 网页通道提交空文件 | ✅ 被拒绝，没有出纸：HTTP **503**，`<TITLE>REQUEST: ERROR</TITLE>`，正文列出有问题的项目（「ファイル」） |
| 3 | 网页通道提交 1 页 JPEG | ✅ 正常打印 |
| 4 | LPD 通道提交 PDF，并指定用户名 | ✅ 正常打印，所有者显示为指定的用户名（本方案不使用，作为参考） |
| 5 | SNMP 读取耗材 | ✅ 碳粉 黑 33% / 黄 **1%** / 品红 **1%** / 青 27%（本方案无法使用 SNMP，作为参考） |

**提交结果的判断**：
- 成功：HTTP 200 且 `<TITLE>` 为 `REQUEST: ACCEPTED`。
- 失败：HTTP 503 且 `<TITLE>` 为 `REQUEST: ERROR`，从正文中提取有问题的项目名，映射为错误代码。

**作业的生命周期**：

```
提交 ──▶ 0 等待 ──▶ 1 打印中 ──▶ 4 完成 ──▶ 从队列消失，进入历史
         约 5 秒      约 5–10 秒
```

**作业归属**：通过网页提交时，打印机把**提交者电脑的 IP** 记为所有者（接口显示为 `HTTP`）。本方案由每个人的浏览器直接提交，所以和现在一样，**每个人的作业记录在各自的 IP 下**，可以区分（v0.1 中转方案会让所有作业都显示为中转设备的 IP，本方案没有这个问题）。

**"我的作业"识别**：返回页面不含作业 ID。新界面提交成功后，把队列里**第一个新出现的作业的所有者（即自己的 IP）**记在浏览器中，之后就能在队列/历史中标出"我的作业"。

### 3.6 对设计有影响的约束

1. **打印机内置 Web 服务器性能弱**：轮询要克制（见 6.3），上传逐个串行进行。
2. **状态值大多是索引**：有利于多语言化，翻译不依赖打印机的显示语言。
3. **少数字段是日文文本**（如「節電中」「普通紙 (60-65g/m²)」）：用映射表转换为代码，遇到不认识的文本时原样显示。
4. **可直接打印的格式**：已确认 PDF、JPEG；TIFF 等待确认。Word / PowerPoint 等 Office 文件**不能**直接打印，需要先另存为 PDF（界面中给出提示）。

## 4. 功能需求

### 4.1 首期（MVP）

#### F1 提交打印
- 拖拽或点击选择文件，**支持一次选多个文件**（按顺序逐个提交）。
- 提交前检查文件格式与大小；不支持的格式（如 `.docx`）提示"请先导出为 PDF"。
- 打印选项（与原界面对应，但更直观）：
  - 份数、逐份
  - 单面 / 双面（长边装订 / 短边装订），附示意图标
  - 黑白 / 彩色 / 自动
  - 纸张尺寸、纸盒、纸张类型（显示各纸盒当前装入的纸张，例如「トレイ1：A4 普通紙」）
  - 打印类型（普通 / 安全打印 / 样张 / 定时），默认折叠在「详细设置」里，见 4.3
- **默认设置：「双面（长边装订）· 黑白 · A4 · 1 份」**（已确认）。
- **快捷预设**：「双面黑白（默认）」「单面彩色」等，一键切换。
- **记住上次的设置**（保存在浏览器的 `localStorage` 里）。
- 提交后显示进度：上传中 → 已发送 → 打印中 → 完成 / 失败。

#### F2 打印机状态
- 设备状态（就绪 / 打印中 / 节电中 / 错误 / 警告），以颜色标签显示在页面顶部。
- 碳粉、感光鼓、废粉盒余量；快用完时醒目提示（例如现在黄色和品红碳粉快用完了）。
- 各纸盒的纸张尺寸、类型与余量；缺纸提示。
- 打印机的警告/通知信息。

#### F3 作业
- 当前队列（自动刷新），标出"我的作业"。
- 作业历史（最近的记录），可筛选"只看我的"。
- 错误历史：错误代码 + 翻译后的说明；没收录的代码显示原始代码。

#### F4 通用
- 语言切换：日语 / 英语（见第 7 章）。
- 浅色 / 深色模式（默认跟随系统）。
- 响应式布局。
- 页面右上角提供「返回原厂界面」链接（刷新页面即可）。

### 4.2 后续阶段（候选）

- Chrome / Edge 浏览器扩展（访问打印机网址时自动切换到新界面）。
- PDF 预览与页数显示（pdf.js）；指定页码范围打印（在浏览器里用 pdf-lib 抽取页面后提交）。
- 图片（PNG / HEIC 等）在浏览器里转换为 PDF 或 JPEG 后打印。
- 第三种语言（中文）。

### 4.3 什么是「安全打印」等特殊打印类型

| 类型 | 原界面名称 | 说明 | 适用场景 |
|---|---|---|---|
| 普通打印 | 通常プリント | 提交后立即打印 | 日常使用（默认） |
| **安全打印** | セキュリティープリント | 提交时设置用户 ID 和密码（数字），作业**先存在打印机里不打印**；本人走到打印机前，在操作面板上选择自己的作业并输入密码后才打印 | 打印成绩单、个人信息、未发表的论文等**不想被别人在出纸盘看到**的文件 |
| 样张打印 | サンプルプリント | 多份打印时**先只打 1 份**，确认没问题后在操作面板上放行剩下的份数 | 一次打很多份（如组会资料 × 10 份）时，避免排版错误导致整批浪费 |
| 定时打印 | 時刻指定プリント | 到指定时间才打印 | 很少用 |

方针：四种都保留，但除"普通打印"外都**折叠在「详细设置」里**，不干扰日常使用。选择安全打印时，在界面上提示"请到打印机操作面板输入密码取件"。

## 5. 系统架构

### 5.1 组成部分

| 组成 | 说明 | 托管位置 |
|---|---|---|
| **书签小程序（Loader）** | 几百字节的 `javascript:` 书签。检查当前页面是不是打印机，然后加载 `portal.js` | 用户的浏览器书签栏 |
| **`portal.js`（新界面本体）** | 打包成单个 JS 文件（CSS 内嵌）。运行后清理旧页面，挂载新界面 | GitHub Pages（免费） |
| **安装页面** | 日/英双语说明 + 可拖拽的书签按钮 + 动图演示 | GitHub Pages |

**没有后端，没有数据库。** 所有数据都实时从打印机读取；用户偏好（语言、上次的设置、自己的 IP）保存在各自浏览器的 `localStorage` 里。

### 5.2 书签小程序的工作流程

```
点击书签
  │
  ├─ 当前页面不是打印机？（检查标题 "Internet Services" / 全局变量 prd 等特征）
  │     └─▶ 弹出提示：「请先打开打印机网页再点击」（日/英按浏览器语言显示）
  │
  └─ 是打印机
        └─▶ 插入 <script src="https://<account>.github.io/print-portal/portal.js?v=<日期>">
              └─▶ portal.js：
                    1. 清除旧页面的定时器（原页面每 120 秒会自动刷新框架）
                    2. 用新的 HTML 文档替换 Frameset
                    3. 挂载新界面，开始读取状态
```

- **更新**：`portal.js` 更新后，用户下次点击书签就会自动用上新版，**不需要重新安装书签**。
- **隐私**：公开托管的代码和安装页面里**不写打印机的 IP**（代码用 `location.origin` 访问当前打印机）。打印机有全局 IP，而且仍在用出厂默认的管理员设置，不宜在公开网页上公布它的地址。打印机网址只在研究室内部告知。

### 5.3 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| UI 框架 | **Preact + TypeScript** | API 与 React 相同，但体积约 4 KB；书签加载要快，体积越小越好 |
| 构建 | **Vite**（库模式，输出单个 IIFE 文件，CSS 内联） | 构建快，开发体验好 |
| 多语言 | **i18next**（配合一个小型 `useT()` hook） | 事实标准；支持复数、插值、语言检测 |
| 样式 | **Tailwind CSS** | 快速实现统一的设计；支持深色模式；旧页面被整个替换，不会有样式冲突 |
| 数据轮询 | 自写的轻量 `usePolling` hook | 需求简单，不引入大型依赖 |
| 测试 | **Vitest**（单元）、**Playwright**（E2E，连接模拟打印机） | — |
| 托管 | **GitHub Pages**（通过 GitHub Actions 自动发布） | 免费、HTTPS、自动部署 |

实测 `portal.js` 压缩后约 **157 KB（gzip 约 51 KB）**，含 Preact、i18next、Tailwind CSS（约 23 KB）与日/英翻译。在局域网/校园网下加载时间可忽略。

## 6. 打印机适配层设计（`src/printer/`）

这部分代替了 v0.1 中的后端，运行在浏览器里。**UI 只通过这一层访问打印机**，以后如果改成浏览器扩展或中转服务器，这一层可以原样复用。

### 6.1 接口（TypeScript）

```ts
interface PrinterClient {
  getStatus(): Promise<PrinterStatus>;        // device + trays + supplies + alerts
  getQueue(): Promise<QueuedJob[]>;
  getHistory(): Promise<HistoryJob[]>;
  getErrorLog(): Promise<ErrorLogEntry[]>;
  submit(file: File, options: PrintOptions,
         onProgress?: (p: SubmitProgress) => void): Promise<SubmitResult>;
}

interface PrintOptions {
  copies: number;                                   // 1-999
  collate: "default" | "on" | "off";
  duplex: "none" | "long-edge" | "short-edge";
  color: "auto" | "color" | "bw";
  tray: "auto" | "T1" | "T2" | "T3" | "T4" | "bypass";
  paperSize: "default" | "A3" | "B4" | "A4" | "B5" | "A5" | "letter" | "legal" | "ledger" /* ... */;
  media: "default" | "plain" | "bond" | "recycled" | "user1" /* ... */;
  delivery:
    | { type: "normal" }
    | { type: "secure"; userId: string; pin: string }
    | { type: "sample"; userId: string }
    | { type: "delayed"; hour: number; minute: number };
}
```

适配层负责把这些语义化的值映射为打印机字段（`duplex: "long-edge"` → `DUP=DP` 等，见 3.3）。**返回给 UI 的都是代码，不是文本**（例如 `state: "sleep"`、`error: "FILE_REJECTED"`）。

### 6.2 页面解析

- 用正则从 HTML 中提取目标变量（`var infoIn=...;`、`info=info.concat(...)` 等）。
- 用一个**只支持字符串、数字、嵌套数组的小型解析器**解析字面量，**不使用 `eval`**（不执行打印机返回的任何代码）。
- 解码字符串中的 HTML 实体（`&sup2;`、`&quot;` 等）。
- **容错**：解析失败或遇到不认识的值时不报错，返回 `{ raw: "原文" }`，UI 直接显示原文。

### 6.3 轮询与负载控制

| 数据 | 刷新间隔 | 说明 |
|---|---|---|
| 设备状态、纸盒、耗材 | 30 秒 | 打印机原界面自身是 120 秒 |
| 作业队列 | 有自己的作业在打印时 3 秒，平时 15 秒 | 用于显示打印进度 |
| 作业历史、错误历史 | 打开对应页面时读取 | — |

- **标签页在后台时暂停轮询**（`document.visibilityState`），避免很多人同时开着页面拖慢打印机。
- 文件逐个串行上传；单个文件上限 100 MB。
- 上传进度：`fetch` 无法获取上传进度，所以提交用 `XMLHttpRequest`（`upload.onprogress`）。

### 6.4 提交流程

```
选择文件 → 校验格式/大小 → 逐个：
   上传（显示进度%）
     ├─ HTTP 200 + "REQUEST: ACCEPTED" → 已发送 → 轮询队列找到新作业 → 打印中 → 完成
     └─ HTTP 503 + "REQUEST: ERROR"    → 失败（提取出问题的项目）→ 显示原因 + 「重试」
   网络错误 → 「无法连接打印机」
```

## 7. 多语言（i18n）设计

### 7.1 基本方针

- 首期语言：**日语 `ja`、英语 `en`**。新增语言只需添加 `locales/<lang>.json` 并在语言列表中登记，**不用改业务代码**。
- **界面上的所有文本都来自翻译文件**，代码里不允许硬编码显示文本（用 ESLint 规则 `i18next/no-literal-string` 检查）。
- **适配层与语言无关**：只返回代码（`state: "sleep"`、`errorCode: "016-788"`），翻译由 UI 完成。即使打印机的显示语言被管理员改成英语，新界面也照常工作。

### 7.2 语言的决定与切换

优先级：
1. 用户手动选择的语言（保存在 `localStorage`）
2. 浏览器语言（`navigator.languages`，如 `ja-JP` → `ja`）
3. 默认：`ja`

切换方式：页面右上角的语言切换器，**每种语言用它自己的名称显示**（「日本語」/「English」）。切换后立即生效，不刷新页面；同时更新 `<html lang>`，影响字体选择和读屏软件。

**安装页面和书签小程序的提示文字**也按同样规则显示日/英文。

### 7.3 翻译文件结构（示例）

键名统一用英文、按功能分层：

### 7.4 细节

- **复数**：用 i18next 的复数规则（英语分 `_one` / `_other`，日语只需 `_other`）。
- **日期、数字**：统一用 `Intl.DateTimeFormat` / `Intl.NumberFormat` 按当前语言格式化，时区固定为 `Asia/Tokyo`。
- **打印机错误代码**（如 `016-788`）：维护一份 `errorCodes` 翻译表（日/英说明 + 建议操作），没收录的代码显示「错误代码 016-788」。
- **专有名词**：如「上質紙」→ "Bond paper"、「セキュリティープリント」→ "Secure Print"，参照 FUJIFILM 官方英文手册的用语，和机身面板上的英文保持一致。
- **布局**：英文通常比日文长 30–50%，按钮和标签允许换行或自适应宽度，不用固定宽度。
- **翻译完整性测试**：单元测试检查 `ja` 和 `en` 的键完全一致。

## 8. 界面设计

### 8.1 设计原则

1. **一屏完成打印**：最常见的操作（选文件 → 确认设置 → 打印）不需要翻页。
2. **默认即合理**：默认「双面（长边）· 黑白 · A4 · 1 份」，多数情况下拖入文件后直接点「打印」即可。
3. **状态一目了然**：打印机状态、碳粉、纸张随时可见，有问题时用颜色 + 图标 + 文字提示。
4. **无障碍**：对比度满足 WCAG 2.1 AA；所有操作都能用键盘完成；表单控件都有正确的 label。

### 8.2 页面结构

三个主页面：**印刷（Print）**、**状态（Status）**、**作业（Jobs）**，单页应用内切换（不刷新页面）。桌面端用左侧导航；窄屏用顶部标签。

## 9. 安全与隐私

### 13.2 实现中的发现

1. **作业可能在被看到之前就打印完了**：小文件在队列中只停留几秒。追踪逻辑为：提交后 0.8 秒首次查询队列；如果一直没在队列中出现，就到作业历史里找"接口为 HTTP、完成时间在提交之后、所有者匹配"的记录作为完成依据（`findFinishedJob`）。同一分钟内的多条相同记录按次数分别对应，不会重复匹配。
2. **"我的作业"的识别**：第一次从本浏览器提交并在队列中找到作业后，记住该作业的所有者（即本机 IP），保存在 `localStorage`。之后队列和历史中都会标出"自分 / You"。
3. **Chrome 的私有网络访问保护**：打印机（公网 IP 段）的页面不能从 `localhost` 加载脚本，因此本地测试时不能直接用书签加载本机构建的文件。正式发布后从 GitHub Pages（公网）加载不受影响。加载失败时书签会弹出提示，原界面仍可使用。
4. **打印机自身的"良好（请准备备用）"状态**：打印机对碳粉的这个状态标记为"良好"。新界面把它显示为**注意**（黄色），以便提早准备碳粉。当前黑、品红、黄三色都处于这个状态。
5. **错误代码说明**：错误代码按前三位（链码）分类显示（如 `071` = 纸盒 1 供纸、`077` = 纸张传送/卡纸）。这是基于 Fuji Xerox 的惯例编写的分类，具体含义应参照机器手册进一步完善。
6. **只接受 PDF 和 JPEG**：TIFF 等格式尚未在真机上验证，因此暂不允许选择，避免打印机收下后又报错。
7. **网页上的碳粉余量是 25% 一档、向上取整的**：与 SNMP 精确值对比（2026-11-25）：

   | | 黑 | 青 | 品红 | 黄 |
   |---|---|---|---|---|
   | SNMP（精确） | 33% | 27% | 1% | 1% |
   | 打印机网页 | 50 | 50 | 25 | 25 |

   感光鼓的网页值与 SNMP 完全一致（58/28/28/27%）；纸盒余量是传感器本身的档位（SNMP 也是 560/420/280 张），两者一致。
   最初版本把网页值直接显示为「25%」，**会让人误以为是精确值**。已改为：碳粉显示为范围（「1〜25%」），进度条实色画到下限、淡色画到上限，并附一行说明。解析逻辑见 `supplyLevel()`。

## 14. 精确碳粉余量（v0.7）

### 14.1 调查：网页上能否直接拿到精确值？

**不能。** 已查过的途径：

| 途径 | 结果 |
|---|---|
| 打印机公开网页（只读爬取 33 个页面） | 只有 `stsply.htm` 有碳粉数据，固件按 25% 一档提供 |
| 计数器页 `prcnt.htm` | 只有累计页数，没有余量 |
| 设置页 `prop.htm` | 需要管理员登录（401），普通成员无法使用 |
| WSD / WS-Print（规范中有精确余量） | 打印机未开启（3702 及常见 WSD 端口无响应） |
| SNMP（精确值来源） | 浏览器和浏览器扩展都不能发送 SNMP 请求 |

### 14.2 方案：开发者本机定时测量并发布

```
开发者的 Mac（在研究室网络时）            GitHub                         用户的浏览器（打印机页面）
 launchd 每小时运行 publish.ts ──SNMP──▶ 打印机
        │ 数值有变化或已超过 12 小时
        └── git push --force ──────────▶ toner-data 分支/toner.json
                                              │ raw.githubusercontent.com（允许跨域，缓存 5 分钟）
                                              └──────────────────────────▶ 每 30 分钟读取一次，与实时档位核对后显示
```

- **发布内容**（`toner.json`）：机型、测量时间、各碳粉/感光鼓的百分比。**不含** IP、序列号、固件版本、用户信息。
- **分支**：`toner-data` 每次强制推送单个提交，不会增长；不触发 Pages 部署，不污染 `main` 的历史。
- **打印机地址**：只写在开发者本机的 LaunchAgent 配置中（`~/Library/LaunchAgents/io.github.print-portal.toner.plist`），不进入仓库。
- **不在研究室网络时**：读不到打印机，脚本什么都不做。

### 14.3 网页端的核对规则（`applySnapshot`）

精确值只有在以下条件都满足时才显示，否则自动退回范围显示：

1. 快照的机型与打印机网页上的机型一致；
2. 测量时间在 14 天以内；
3. 精确值落在打印机**实时**报告的档位范围内（允许 ±1% 的取整误差）。例如实时为「1〜25%」，快照为 1% → 显示「1%」；如果换了新碳粉（实时变为「76〜100%」），旧快照的 1% 不再一致 → 显示范围。

显示精确值时，在下方注明测量时间（如「正確な値は3 時間前に測定したものです。」）。

| 安装/更新每小时任务 | `npm run toner:install -- <地址>` |
| 卸载 | `scripts/toner/install-agent.sh --uninstall` |

### 14.5 实现中的一个坑

`net-snmp` 的遍历回调如果返回 `true`，表示"停止遍历"。最初为了满足类型定义加了 `return true`，结果只读到第一批数据就停止了，表现为"找不到碳粉数据"。已修复并加注释说明。

### 14.6 补充：碳粉状态的判断依据与 SNMP 警报

- 「良好」「残りわずか（予備を用意）」是**打印机自己的判断**，新界面只是照着显示。实测黑 33% 被标为"请准备备用"，而青 27% 为"良好"。按剩余百分比或剩余张数（黑 8,580 张 / 青 4,050 张）都解释不了，最可能的是打印机**按消耗速度估算剩余可用时间**：黑色每一页都会用（累计黑白 114,373 页，彩色页也用黑色）。打印机没有公开具体判断标准。
- SNMP 警报表（`prtAlertTable`）中，打印机对黑/黄/品红发出了 093-406/407/408「即将需要更换，请订购」，青色没有，和上面一致。
- **警报表里有网页上看不到的信息**：094-421「转印带清洁器已到寿命，请联系管理员更换（仍可打印）」。网页的通知栏为空，耗材页也没有这一项。可以考虑把警报一起放进本机发布的快照（待决定）。

## 15. 个人信箱：扫描文件的保存与下载

### 15.1 背景

ApeosPort 的「ボックス」（信箱）功能可以把扫描的文件保存到带密码的个人信箱，再从网页下载。研究室已经在用（有约 28 个信箱，多数以成员名字命名）。原厂界面操作繁琐（Frameset、多层表单），因此在新界面中提供更好用的信箱页面。

### 15.2 调查结果（2026-11-25，用测试信箱调查，信箱中尚无文件）

所有接口都是普通的 HTTP 表单，新界面运行在打印机页面内（同源），可以直接调用。

| 步骤 | 接口 | 参数 | 返回 |
|---|---|---|---|
| 信箱列表 | `GET scpblst.htm` | — | `var box=[[编号, 名称, 文件数(有密码时为空), ?, ?], …]` |
| 请求打开信箱 | `POST PBDOCLST.cmd` | `BOX, ORD=DD, SET=1, LTOP, LNUM, PAGE` | 有密码的信箱返回密码输入页 |
| 输入密码 | `POST PBPWD.cmd` | `PWD, SET=1, BOX, ORD` | 正确：文件列表页；错误：HTTP 503 + `REQUEST: ERROR`（与上传失败格式相同） |
| 文件列表 | （上一步的返回页） | — | `var box=[编号, 令牌, 排序, ?, 名称, ?]`，`var lst=[[文件号, 扫描时间, 压缩方式索引, 页数, 类型索引, 文件名, 可高压缩, ?, 可少数色], …]` |
| 下载（第 1 步） | `GET PBDOCLNK.cmd` | `BOX, PWD=令牌, ORD, DOC=文件号/文件号/…, FORM=PDF\|TIFJPG, PAGE, SMNL=0, HCMP=0, ICMP=0, NCOLOR=false` | 页面中 `var info=[[信箱, 文件号, 页, 文件名, '/box/<随机串>/<文件名>.pdf'], …]`，**每个文件一个链接** |
| 下载（第 2 步） | `GET /box/<随机串>/<文件名>.pdf` | — | `application/pdf`，`Content-Disposition: attachment`；链接可重复下载 |
| 删除 | `POST PBDOCRM.cmd` | `BOX, PWD=令牌, ORD, DOC=文件号/…` | 成功：HTTP 200 + `REQUEST: ACCEPTED`；打印机忙时被拒绝：HTTP 503「設定モードに移行できません」（见第 6 条） |
| 从信箱打印 | `POST PBDOCPRT.cmd` | `BOX, PWD=令牌, DOC, 份数, 双面 …` | 待确认 |

关键发现：

1. **没有会话或 cookie**。密码正确后，页面里返回一个令牌，之后下载、删除、打印都把它作为 `PWD` 参数提交。
2. **令牌每次都相同**（同一密码两次登录结果一致），即**令牌等同于密码**。必须按密码对待。
3. 一次最多选择 9 个文件下载或打印（`dMax=9`）。
4. 下载格式：PDF、TIFF/JPEG（部分机型还支持 DocuWorks，本机未提供）。
5. 打印机只有 HTTP，信箱密码以明文在局域网中传输。
6. **删除需要打印机空闲**：操作面板正在使用、Smart WelcomEyes（人体感应）检测到有人、有作业执行中，或**有人在原厂网页上打开着信箱**时，打印机拒绝删除（需要进入"设定模式"）。实测中的原因是在原厂网页上开着信箱，关闭后删除立即成功。此时打印机状态显示「パネル操作中です」。界面需要：给出明确原因并提示稍后重试；面板使用中时可预先提示。下载、列出文件不受影响。
7. 下载**不会**自动删除文件（本信箱未开启"取出后删除"；其他信箱可能不同，界面应在下载后重新读取列表）。
8. 实测（2026-11-25）：1 页与 2 页扫描文件均以 PDF 正常下载；多选 2 个文件时返回 2 个链接。这一点原厂界面也一样，无法改变；应提醒大家不要使用与其他重要账号相同的密码。

### 15.3 功能设计（草案）

新增导航页「ボックス / Mailbox」：

1. **选择信箱**：列出信箱（编号 + 名称）。用户可以把自己的信箱设为"我的信箱"，记住**编号**（`localStorage`），之后直接跳到密码输入。

## 17. PDF 处理与 SNMP 警报（v1.1）

### 17.1 设置调整

- **颜色默认改为「自動」**（原为黑白），选项顺序改为「自動 / カラー / 白黒」。已经用过的浏览器会沿用各自记住的设置。
- **去掉「よく使う設定」**：它只是把下面的「両面」「カラー」两个一键选项再捆绑一次，颜色默认自动后意义更小。

### 17.2 PDF：页数、页码指定、1 枚に複数ページ、预览

全部在浏览器中完成，打印机不需要支持这些功能。

| 功能 | 说明 |
|---|---|
| 页数 | 加入 PDF 后自动读取，显示「全 N ページ」 |
| 页码指定 | 每个 PDF 一个输入框，如「1-3, 5, 8-」；支持全角数字和「〜」「、」。超出页数或格式错误时显示原因，并阻止打印（不会悄悄忽略） |
| 1 枚に 2 / 4 ページ | 设置项「1 枚に印刷するページ数」。自动选择纸张方向使每页最大：纵向页面 2 合 1 时横向排列；横向幻灯片 2 合 1 时上下排列；4 合 1 为 2×2。正确处理带旋转的页面；空白页保留空位 |
| 仕上がりを確認 | 用浏览器**自带的 PDF 查看器**（iframe）显示实际要发送的 PDF，不需要额外的渲染库 |
| 用纸估算 | 总结中显示「用紙は約 N 枚です」（考虑页码指定、每张页数、双面、份数） |
| 不需要处理的文件 | **原样发送，不重新编码**（端到端测试验证文件字节数一致） |

**实现**：`pdf-lib`（MIT）。为了不增加首次加载时间，单独打包为 `pdf-tools.js`（gzip 约 177 KB），第一次加入 PDF 时才从 `portal.js` 所在位置加载（`src/pdf/loader.ts`）。加密 PDF 和无法解析的 PDF 不能使用这些功能，但仍可原样打印，界面会说明原因。

~~**待真机确认**：2 合 1 + 双面时，横向输出页面的翻面方向是否符合预期。~~ 已确认并修正，见 17.4。

### 17.3 SNMP 警报

本机发布的快照（第 14 章）新增 `alerts`：读取 Printer MIB 的 `prtAlertTable`，只保留"警告""严重"级别（"节电模式中"等普通信息被过滤）。状态页「プリンターからのお知らせ」中，网页本身没有的警报以「代码 + 日文分类 + 打印机原文（英文）+ 取得时间」显示；网页已有的代码不重复显示。快照超过 14 天或机型不一致时不显示。

### 17.4 真机测试：2 合 1 + 双面的翻页方向（2026-11-25）

用新界面（线上正式版书签）打印 8 页测试 PDF（每页印有大号页码和朝上的箭头），设置为「1 枚に 2 ページ・両面（長辺とじ）・白黒・A4」：

- 打印成功：打印机历史记录为 4 面（2 张纸）、正常结束、接口 HTTP，所有者为提交者 IP；新界面在约 20 秒内显示「印刷しました」。这也是新界面在真机上的第一次完整打印验收。
- **翻页方向为日历式（上下翻）**。原因：打印机的「長辺とじ」是相对于**纸张本身**的长边；2 合 1 时内容横着排在纸上，纸的长边就是内容的上边。
- 2 合 1 的讲义、论文在日本也一般是像书一样左右翻（横排文字左侧装订）。

**对策**：输出纸张为横向时（纵向文档 2 合 1），发送给打印机的装订方式自动对调（`duplexForPrinter`）：用户选「長辺とじ」→ 实际发送「短辺とじ」（`DUP=TB`），翻页为左右翻，和平时单页双面的感觉一致。横向幻灯片 2 合 1（上下叠放在纵向纸上）和 4 合 1（纵向纸）不受影响。纸张预览中的装订标记也按用户看到的效果显示在左侧。

### 17.5 问题：发布后预览失败（`portal.js` 与 `pdf-tools.js` 版本不一致）

**现象**（用户报告）：4 页 PDF 填写页码「4」后预览报错（浏览器的 PDF 查看器显示加载失败并提示重新加载）；页码空着时正常。刷新后回到原厂界面，已选文件丢失。过一段时间后自动恢复正常。

**原因**：两个文件由浏览器分别缓存（GitHub Pages 的 `max-age=600`，即 10 分钟），而 `pdf-tools.js` 的请求地址使用固定的版本号 `0.1.0`，每次发布都不变。17.4 的修正改变了 `preparePdf` 的返回格式（从 PDF 字节改为 `{ bytes, landscape }`）。发布后 10 分钟内，新的 `portal.js` 可能配上缓存中的旧 `pdf-tools.js`，生成的"文件"不是 PDF。页码空着时不需要加工，直接使用原文件，所以不受影响。

**风险**：如果当时不是预览而是打印，打印机会收到无效文件。

**对策**：

| 对策 | 说明 |
|---|---|
| 构建编号 | 每次构建生成唯一编号（CI 中为提交 SHA），两个文件共用；`portal.js` 只请求同一次构建的 `pdf-tools.js?b=<编号>` |
| 接口版本核对 | `pdf-tools.js` 带 `apiVersion`（`src/pdf/api.ts`），与 `portal.js` 不一致时拒绝使用，提示「新しいバージョンに更新されました。ページを再読み込みしてから、もう一度ブックマークをクリックしてください。」 |
| 输出校验 | 加工结果必须以 `%PDF-` 开头，否则报错，绝不上传 |
| 不悄悄忽略设置 | PDF 工具加载失败或版本不一致时，需要加工的文件标记为打印失败，而不是按原文件 1-up 打印（加密/无法解析的 PDF 仍按原样打印，界面已说明） |
| 离开前确认 | 有待打印或正在发送的文件时，刷新/关闭页面会弹出浏览器的确认框（刷新会回到原厂界面） |
| 预览备用入口 | 预览框中提供「新しいタブで開く」，用于无法在页面内显示 PDF 的浏览器 |

端到端测试中加入了重现此问题的用例：注入旧版 `pdf-tools.js` 后，界面提示刷新，文件标记为失败，打印机未收到任何上传。

**今后的规则**：修改 `pdf-tools.js` 提供的函数签名时，必须同时增加 `PDF_TOOLS_API`。

### 17.6 问题：只打印大文档中的几页，仍然很慢（上传了几乎整个文件）

**现象**（用户报告）：大文档只打印 1 页或几页时，上传很慢，好像把整个文件都传了。

**原因**：很多 PDF 生成软件把整份文档的图片和字体放在**一个所有页面共享的资源表**里。`pdf-lib` 复制页面时会连同整张资源表一起复制，所以"只有 1 页"的输出和原文件几乎一样大。

**实测**（40 页、每页一张约 400 KB 图片）：

| PDF 结构 | 原文件 | 只取第 1 页（修正前） | 只取第 1 页（修正后） |
|---|---|---|---|
| 每页独立资源 | 15.6 MB | 0.39 MB | 0.39 MB |
| 所有页共享资源 | 15.6 MB | **15.56 MB** | **0.39 MB** |

**对策**（`src/pdf/prune.ts`）：复制页面前，读取页面内容（解压后）中出现的所有名称，资源表中只保留被引用的图片、字体、图形状态等；页面所绘制的、借用页面资源的表单对象也会递归检查。规则保守：出现过的名称一律保留；页面内容无法解压时该页不做精简。2 合 1 / 4 合 1 同样受益（共享资源文档的 2 页 2 合 1：0.78 MB）。

**测试**：单元测试覆盖图片、字体、借用页面资源的表单、无法解压的内容；端到端测试确认约 6 MB 的共享资源 PDF 只打印 1 页时，打印机收到的文件不到原文件的 1/10。

## 18. 信箱：缩略图、预览、文件命名（v1.5）

### 18.1 调查（2026-11-25，027 号测试信箱）

| 能取出的文件类型 | 只有扫描、传真、邮件文件（打印机自身的判断：类型索引 ≥ 2）；保存的打印作业不能取出 |

### 18.2 实现

| 功能 | 说明 |
|---|---|
| 缩略图 | 只取每个文件的第 1 页，用 **pdf.js**（Apache-2.0）渲染成小图。扫描件多为黑白 MMR 压缩，浏览器不能直接显示，因此需要 pdf.js。逐个生成（同时只有一个请求），最多 40 个 |
| 预览 | 点缩略图或「表示」，取出整个文件，在浏览器自带的 PDF 查看器中显示（与印刷页共用 `PdfDialog`），对话框中可直接保存 |
| 命名 | 打印机不支持，因此改为**在本浏览器中命名**：按「信箱编号 + 打印机文件名」保存在 `localStorage`，列表中显示该名字（下方注明扫描时间），下载时也用作文件名（替换文件名中的非法字符）。已删除文件的名字会被清理。界面注明"只保存在这台浏览器，打印机上的文件名不变" |
| 隐私 | 缩略图和预览只在内存中，关闭信箱即清除，与密码相同 |
| 打包 | pdf.js 单独打包为 `pdf-view.js`（gzip 134 KB），worker 为 `pdf.worker.js`（gzip 约 380 KB），**只在信箱中有文件时加载**。浏览器不允许跨源启动 worker，因此先下载 worker 代码，再从 `blob:` 地址启动。与 `pdf-tools.js` 相同，使用构建编号和接口版本（`PDF_VIEW_API`）防止新旧版本混用 |
